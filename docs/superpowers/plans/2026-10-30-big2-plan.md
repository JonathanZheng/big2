# Big 2 Plan

Two projects that share one rulebook:

1. **Model upgrade:** a strong bot under the house rules, small enough to run in the browser. Design: `docs/superpowers/specs/2026-10-30-model-upgrade-design.md`.
2. **New web app:** rebuilt from scratch (the current `big2-web` stays as reference only), running the trained bot in the browser.

Order: engine and training first, the app while training runs, then plug the trained model into the app.

## Findings that shaped the plan

| Finding | Evidence |
|---|---|
| The old best model is no better than the bots | `big2_model.pt`: 25.8% vs 3 greedy (400 games), 30.6% vs 3 rule-based (160 games), 21.7% vs 3 Smart (2,000 games). 25% is break-even. |
| Its recorded 31.5% was luck | Picked as the best of many 200-game evaluations, where noise is about 6% either way. |
| Old training was throttled by the rule-based bot | 6.7 s per game vs 16 ms for self-play; it brute-forces every possible 5-card combination of unseen cards. |
| A GPU does not help at this size | On the M3: same training step speed, 16x slower at scoring moves for a 0.25M-parameter model. A GPU only pays off around 3M+ parameters. |
| Smart (Patwa 2026) is the strongest available test opponent | 31.3% as 1 Smart vs 3 greedy; greedy gets 19.2% as 1 vs 3 Smart (2,000 games each). Charlesworth 2018 uses different rules, so it cannot be used. |
| Four of a kind was broken in the engine | Always detected as invalid: playable on top of straights, flushes and full houses, and then unbeatable. Fixed. |

## Decisions

- **House straight order:** 3-4-5-6-7 < ... < 10-J-Q-K-A < J-Q-K-A-2 < 2-3-4-5-6 < A-2-3-4-5. Same run: suit of the highest card (the 2 when present). Straight flushes use the same order. Q-K-A-2-3 and K-A-2-3-4 are not straights.
- **Training:** Deep Monte Carlo self-play only. Bots are test opponents only.
- **Evaluation:** 2,000 games per matchup, random seats, 95% margins. Opponents: Smart, the old model, and the previous best new checkpoint. Greedy and rule-based bots are no longer used routinely.
- **Model size:** at or below about 1M parameters (currently 715K) so it runs in TypeScript.
- **Hardware:** CPU. JAX is out of scope.

### Running and monitoring

```bash
python3 train_selfplay.py --hours 8          # resumes from checkpoints/selfplay/latest.pt
tail -f checkpoints/selfplay/train.log       # throughput and loss
cat checkpoints/selfplay/benchmarks.log      # every saved checkpoint vs Smart and the old model
pkill -INT -f train_selfplay.py              # stop early with a final save
python3 benchmark.py <checkpoint> --vs smart old <other checkpoint>
python3 -m pytest tests/
```

### Success criteria

- Above 32.5% against 3 Smart bots (the paper's Monte Carlo result), with the margin clear of 25%.
- Clear of 25% against 3 copies of the old model.
- Each new best beats the previous best head-to-head.

## New web app: status

Requirements so far:

- The trained bot runs in the browser, with no server.
- **Board Setup / Analyzer** (requested): choose my hand, mark played cards, set each opponent's card count (default 13), set the move currently on the table and who played it; the bot ranks my options.
- **Play vs Bots** (requested): me against 3 bots.
- The current `big2-web` look is not liked; this is a fresh design.

Proposed, not yet confirmed: difficulty levels (Smart as Easy or Medium, the trained model as Hard), a hint button during games, game replay with the moves where the bot would have played differently, watching bots play, hand helpers (sort, highlight combos), local stats in the browser. Proposed to leave out at first: accounts, ELO and online multiplayer.

Open questions:

1. Main use of Board Setup: on a phone at a real table, or at a desk afterwards. This decides mobile-first vs desktop layout.
2. Which proposed features to keep.
3. Visual direction.

Next step: finish the app design conversation, write its design document, then build.
